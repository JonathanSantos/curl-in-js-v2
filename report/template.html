A ideia

Todo mundo que depura uma API no DevTools conhece o gesto: botão direito na requisição, Copy as cURL, colar no terminal. O curl-in-js leva esse gesto para dentro do JavaScript. O comando colado vira o próprio argumento da função, sem aspas extras, sem converter nada à mão.

O arquivo de teste original é a melhor documentação do projeto. Ele continua aqui, do jeito que foi escrito:

A crase logo depois de curl é o projeto inteiro. É um tagged template: o JavaScript chama a função curl entregando o texto entre as crases. Bibliotecas como styled-components e graphql-tag já tinham popularizado a técnica para CSS e GraphQL; em 2021 o zx, do Google, fez o mesmo com comandos de shell. O curl-in-js aplica a ideia a um formato que ninguém precisa aprender, porque o navegador já escreve por você.

O que admiro neste código

1. A interface é o formato que o navegador já escreve

O melhor design de API aqui foi não inventar uma. A assinatura usa desestruturação direto no parâmetro para pegar o primeiro pedaço do template:

2. Um parser que cabe em uma expressão regular

Esta linha sustenta o projeto:

Ela funciona por causa de um detalhe sutil da linguagem. Dentro de um template literal, uma barra invertida no fim da linha é uma continuação: o JavaScript apaga a barra e a quebra de linha. Sobra a indentação que o DevTools coloca antes de cada -H. Então “dois ou mais espaços” vira o separador entre argumentos, e o comando se divide sozinho em linhas limpas. Entender o formato do Chrome bem o bastante para resolver o problema com um split é uma leitura esperta do terreno.

3. Pipelines com nome em cada etapa

Cada função declara pequenos passos e depois os encadeia. Leia só o return e você tem a descrição do algoritmo em quatro verbos:

Tem bastante técnica concentrada nessas linhas: funções puras, estilo point-free (os passos entram por nome, sem x => f(x)), desestruturação de array no parâmetro, propriedade computada em { [key]: value } e um reduce que monta o objeto sem mutar nada. Era o JavaScript funcional que a comunidade estava aprendendo a gostar em 2021.

5. A divisão em dois arquivos

utils.js só transforma texto em dados. curl.js é o único que fala com a rede. Essa separação tem nome, functional core, imperative shell, e já estava ali em 68 linhas. Foi ela que permitiu rodar o parser de 2021 dentro deste relatório, no navegador, sem tocar em uma linha: ele nunca dependeu do Node.

6. O método inferido

Sem -X, um comando com corpo vira POST. É exatamente a regra do curl de verdade, reproduzida em uma função de dez linhas. E há um charme extra nela: normalizeLineMethood, com dois “o”, ficou preservado na pasta original/ como estava.

O que foi refeito

A regra da reescrita foi manter a experiência de quem usa e trocar o que está por baixo. O split por indentação deu lugar a um caminho com etapas pequenas, em que só a última toca a rede:

núcleo puro: texto entra, dados saem
curl`…${x}…`→ segmentos→ tokenize→ argumentos→ tabela de opções→ rascunho→ requisição imutável
casca: a única parte com rede
fetch→ { data, status, ok, headers }

As mudanças, uma por uma

  • Tokenizer de shell. Lê aspas simples, aspas duplas, o $'…' que o Chrome usa quando o corpo tem apóstrofo ou quebra de linha, e a barra de continuação. O comando pode vir em uma linha, em dez, com ou sem indentação.
  • Template lido cru. A versão nova usa strings.raw. Um \n dentro de um corpo JSON chega ao parser como o shell entregaria, em vez de virar uma quebra de linha de verdade e invalidar o JSON.
  • Interpolação segura. ${valor} entra como um argumento só, sem ser reinterpretado. Um token com aspas ou espaços não consegue “escapar” e injetar outra opção. Objetos viram JSON.
  • Mais do curl. -X, -H, -d e variações, --json, --data-urlencode, -G, -I, -u, -A, -e, -b, --max-time, opções agrupadas (-sSL) e a forma --opcao=valor.
  • fetch nativo. O axios saiu. O projeto não tem nenhuma dependência e o mesmo núcleo roda no Node, no Deno, no Bun e no navegador.
  • Falhas com nome. CurlSyntaxError diz o que faltou no comando. CurlRequestError guarda a causa original e a requisição que falhou.
  • Testes que rodam sozinhos. {{TEST_COUNT}} testes com node:test, sem internet: unitários do tokenizer e do parser, o curl com um fetch de mentira, e quatro de ponta a ponta contra um servidor HTTP local.

O que ficou igual, de propósito

  • O nome, a tag curl`…` e o retorno { data, status }, inclusive para respostas de erro.
  • A pasta src/curl/ com curl.js e utils.js, e as funções getURL, getHeaders, getBody e getMethod. Um teste garante que elas devolvem para o comando de 2021 o mesmo que devolviam.
  • O estilo: funções pequenas, puras, com nome, encadeadas.
  • O Ditto. O comando do teste original virou examples/pokemon.js e respondeu 200 na PokéAPI em 10 de novembro de 2026, com os cabeçalhos do Chrome 89 e tudo.
  • O código de 2021, intacto, na pasta original/, com os nove commits preservados no histórico.

O que ainda não faz

Para ser justo com quem for usar: -F (multipart) e corpo lido de arquivo (-d @arquivo) lançam erro explicando que não são suportados. O formato “Copy as cURL (cmd)” do Windows, com ^, não é lido. Redirecionamentos são sempre seguidos, como o axios fazia, mesmo sem -L. E no navegador o fetch descarta cabeçalhos que só o próprio navegador pode definir, como User-Agent e Referer.
